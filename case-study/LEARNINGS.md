# Learnings log

Every self-audit reads this first and adds to it last. One line per lesson: date, what happened, what to do next time.

- 2026-09-26: Force-resetting the branch orphaned commits. Check `git log origin/main..HEAD` before any reset.
- 2026-09-26: A made-up stat ("Now: 100 brands") slipped into copy. Every number needs a source.
- 2026-09-26: A pronoun was assumed from a name. Use "they" unless stated.
- 2026-09-26: A grid overflowed on mobile. Grid children need `min-width:0`; test at 390px.
- 2026-09-26: Chat escalation emailed Virat an approve link only for phone contacts; email contacts had no way in. Every escalation path needs an approve link for every contact type, and a test for each.
- 2026-09-26: /mission read as a wall of text. Give every big idea a picture (inline SVG or tinted tile), and link the mission from one shared band (.vm-mission in tokens.css) so the wording stays the same everywhere.
- 2026-09-26: A lead-reply recap quoted the lead's own "we" and failed the voice check. Retell their words in second person, and run voiceIssues() on every draft before it reaches Gmail.
- 2026-09-26: A CSV parser dropped every Shopify order because order names start with '#', the same as GA4 comment lines. Strip comment lines only before the header, and test each real export format.
- 2026-09-26: Emails sent from Gmail drafts arrived with every link wrapped in a google.com/url redirect notice and the logo image stripped: Gmail rewrites drafts saved through the API. Send with send_message/reply directly, or write links as bare URLs; only use drafts when Virat must add the recipient.
- 2026-09-26: Brand status copy ("Moonglasses runs on the full system") lived in five places and drifted. Brand status has one source: the FAQ answer in faq-data.js; the chat prompt, DevShop proof card and Brain seed quote it.
- 2026-09-26: A brand report died with a bare "Invalid API key". Read every stored key before use (decode the project ref, compare with the URL) and show a Connections panel so the admin names the exact fix. Isolate each brand's failure from the others.
- 2026-09-28: I thanked Korbi for a "signed NDA" that had only the company name and address filled in; both signature blocks and the date were blank. Open every returned contract and check each signature line and date before replying or countersigning.
- 2026-09-26: Access-request and plan drafts were parked in lead_messages with no way to send them (the approver only knew Gmail drafts). Every draft now goes through one submitForApproval() that signs the link, tells Virat, and sends fresh from Gmail on approval; the journey is one list (lead-journey.ts) with a 7-day clock from NDA signed + data connected.

- 2026-09-26: Employee Support Agent: team questions used to go only to Virat, so a new hire waited on him for things the Brain already knew. Rule: a team question gets a sourced Brain answer by email first; only unanswered ones nudge Virat, and both land in the 9:30 team report.
- 2026-09-26: Brand work was scattered across Gmail, Supabase and the ops board with no single record. Each brand now gets one file in `case-study/brands/` that cites where every fact came from.
- 2026-09-27: A scripted text replace used the first "</summary>" in the file as the end marker and matched an empty range, so the "replacement" was inserted between every character of a 130-line page (it became 10,000 lines). Never slice by the first match of a common tag; anchor on a unique string, and assert the slice is non-empty before replacing.
- 2026-09-27: Astro's compiler broke the build ("Expected ) but found }") when a table sat inside a .map() with more rows or tables after the loop. Keep loops over rows in their own table and put forms outside tables. Also: when reorganising someone's task page, only add fields (objective, priority); never rewrite their statuses or notes.
- 2026-09-27: A commercial-terms change (retainer from ₹100 Cr+ a year) typed a new number into generated plan text; the number-trace check flagged it and 6 tests stayed red unnoticed. Every published threshold gets one named source (STANDARD_TERM_CONDITIONS in lead-plan.ts; commercial status held separately), and generated text quotes that source instead of copying the number. The number-trace test is the regression control for "never invent numbers": keep it green, and have CI run it on every push. Being a traceable source is not commercial approval.
- 2026-09-28: The reel first led with Travaholic's +59%, but Ceremony Kitchen's ROAS doubling was the stronger proof and I hadn't checked it. Before picking a headline stat, check every live brand's before/after (admin console or each brand's database), then pick the fairest window: vs the 30 days before, not a flattering 3-day low.
- 2026-09-28: The first soundtrack mix was bass-heavy and 2 dB hotter than platforms play back; on a phone speaker the lows vanish. Measure per-band loudness before muxing: keep lows and mids level, hats audible, and the whole at about −14 LUFS.
- 2026-09-28: A brand went live (India Contemporary) and its status sat as "Launching" in five places. When a status changes, update the FAQ source first, then every place that quotes it (chat prompt, DevShop stats, /retail-os chips and grid) in the same commit, and grep for the old wording before pushing.
- 2026-09-28: Two synthesised soundtracks and a GM-sample piano were rejected as sounding like MIDI. I can't hear audio, so I can't judge music; a premium brand needs a real, licensed track picked by ear. Build the video so cuts can snap to any track's beats, and ask for the track.
- 2026-09-28: A reel went out with a blank orange Instagram cover because frame 0 is plain (for a seamless loop) and Buffer can only pick a frame, not upload a cover. For Instagram, open the video with a 0.8 s cover title card and set thumbnailOffset to it (devshop-retail-os-reel-ig.mp4, cover.html); keep the loop version for the site.
- 2026-09-29: Daily founder update. Every live brand gets a daily update to its founder from the day they sign, embedded in the email body (not an attached document), in the viratmohan.com aesthetic. Each item says what I did and why it matters to the business; end on real last-24h numbers (label sample as sample) and invite a reply. Thin activity is not a reason to skip or pad: a near-empty update is the signal to pay that client more attention and drive them toward profitability, said honestly. Comments come back by reply; fold them in with judgment and nudge Virat. Sent from viratmohan@gmail.com with the founder@ signature until founder@ sending is wired. Built into Retail OS: subscription at signing, a daily cron, and a per-brand journey page.
- 2026-09-30: The Korbi proposal draft lost its inline QR: Gmail drafted through the API drops <img src="cid:…"> and gives the inline part its own Content-ID. In a draft, attach images as files and say "attached"; embed images only in emails sent directly with send_message. Keep attachments small (a 24-colour PNG of the QR is 13 KB and still scans), because base64 goes through the tool call.
- 2026-09-30: Virat had to add the QR to the Korbi proposal by hand because the API draft had stripped it. Rule (CLAUDE.md, "Proposals and payment emails"): every proposal embeds the hosted deposit QR (https://www.viratmohan.com/retail-os/pay/deposit-qr.png) in the body and goes through submitForApproval, not an API-made Gmail draft.
- 2026-09-30: Virat's edits to the Korbi proposal, before sending: (1) NDA and deposit come first, with the payment screenshot sent by reply or WhatsApp; access and data only after, and the apply/terms-page steps were cut. Don't hold the payment behind other steps. (2) A warm opener from the call ("Great talking to you guys. Excited about building this!"). (3) The client's launch price went to "TBD": don't publish their price as fact. (4) The break fee reads "5% of revenue to date less the profit share already taken". (5) The data ask is labelled "post signup". The standard is now in CLAUDE.md, "Proposals and payment emails".
- 2026-09-30: Every client question gets logged, per brand, in case-study/clients/<brand>.md (date, who, question, written answer, date answered). Korbi was the first.
- 2026-09-30: The brand page showed an auto-generated quarterly forecast before Virat had checked it, and pushed brands with their own store to pick a new design. Rule: nothing numeric reaches a brand until Virat stands behind it (forecast shows after the deposit is confirmed), and an existing brand's design ideas are optional suggestions.
- 2026-09-30: I asked Virat for Srishti's email when it was already in his inbox. Before asking Virat anything, search Gmail, Supabase and the repo first; ask only what can't be found.

- 2026-09-30 · Virat's social sync: a read-only integration enforces "read only" in code (a path allowlist plus GET-only), not in a comment, so ads or boosting can never be called by accident. Content rules (D2C only, no brand names, % only, ends "DM me D2C") are a checkCopy() function the brief must pass, with tests.
- 2026-09-30: A merge left conflict markers in CLAUDE.md because I only cleaned the file I expected to conflict. After any merge, grep the whole repo for <<<<<<< before committing.
- 2026-09-30: Tying the forecast to the deposit revealed it the moment I recorded Fresh For Paws' payment, though Virat still wasn't sure of it. Anything Virat hasn't approved needs an explicit release flag (terms.forecastReleased), never a side effect of another event.
- 2026-09-30: When Anun asked to remove COD I argued to keep it before doing it. Don't argue with a client or partner unless there's an amazing, memory/standard-backed reason — do what they asked, and flag a concern in one line at most. Also: COD is off across Retail OS (India RTO/logistics); storefronts are prepaid/UPI only, gated by a single COD_DISABLED flag per store, admin orders unaffected. Turn it back on only if Virat says so.
- 2026-09-30: I sent Prince task emails and quick client replies as plain text. Every email — to Virat, team or client — uses the viratmohan.com branded template (renderRetailOsEmail), summarised and action-first; plain text is only the fallback twin. No unbranded email, ever.
- 2026-10-01: Korbi asked for a fixed fee per unit and Virat agreed (₹1,000 per unit sold online). Terms now support a per-unit fee (terms.perUnitFeeInr) as a reusable commercial model; record every agreed term in the client file the same day.
- 2026-10-01: Signed-terms alerts went to whatever ADMIN_NOTIFY_EMAIL held, and the founder's copy had no cc, so Virat's business inbox could miss a signature. Client and signing emails now always reach founder@viratmohan.com (FOUNDER_INBOX in retail-os-email.ts); env addresses only get copies.
- 2026-10-01: The Fresh For Paws backend couldn't get its own Supabase project (create timed out twice) or GitHub repo (403 for the integration). I built it as code staged in retail-os-brands/freshforpaws/, so creating the project is one apply. - 2026-10-01: A Korbi email linked a page that was deployed after the email went out, so it showed 404. Deploy, load the live URL, then send. The mail sender now blocks any email whose links don't load (link-check.ts).
- 2026-10-01: Caps' WhatsApp runs on MSG91, not the Cloud API, so 'reuse the Caps inbox' wasn't possible. Check what a module actually runs on before naming it the reference implementation. The core WhatsApp inbox now lives in the master repo (src/lib/whatsapp-inbox.ts, /retail-os/admin/inbox).
- 2026-10-02: Brand drift happens when copy is written from memory. Every brand now has one brand book module and a checker that blocks sends; ask the founder about gaps, never guess.
- 2026-10-02: I resized a photo into a frame with a different shape and it stretched. Always crop to the frame's exact proportions first, then resize.
- 2026-10-02: Travaholic lost about 87% of started payments inside Instagram/Facebook in-app browsers, which block the Razorpay popup. Ask for brand assets to be shared to viratmohan@gmail.com and tech@viratmohan.com by name, and keep brand colours in one token file so unverified values are swapped in one place.
